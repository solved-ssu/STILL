# 보고서 기반 개선 TDD 증거

## 출처와 사용자 여정

- 출처: [`repoty-by-claude.md`](../../repoty-by-claude.md)
- 별도 계획 파일은 사용하지 않았고, 보고서와 사용자의 그래프 상호작용 추가 요청에서 보증을 도출했다.
- 구성원은 초기 전화번호 비밀번호를 본인만 아는 비밀번호로 바꾸고 새 비밀번호로 다시 로그인할 수 있다.
- 키보드 사용자는 모든 폼의 현재 포커스를 볼 수 있다.
- 문서 열람자는 실제 조회수가 증가하고 의미 있는 탭 제목을 볼 수 있다.
- 손상된 블록이나 제한을 넘는 요청은 문서를 망가뜨리지 않는다.
- 홈 사용자는 그래프 노드와 캔버스를 포인터로 움직이고 키보드로 노드를 이동할 수 있다.
- 사용자는 대주제 안의 소주제를 탐색하고, 문서를 올바른 소주제에 분류할 수 있다.
- 홈 사용자는 대주제–소주제–문서가 힘에 따라 재배치되는 모습을 보고 움직임을 정지·재생할 수 있다.
- 모바일 사용자는 두 손가락 중점을 유지하며 그래프를 확대·축소할 수 있다.
- 사용자는 노드 이름을 검색해 결과를 키보드로 선택하고 해당 노드로 카메라와 포커스를 이동할 수 있다.
- 문서 작성자는 본문의 내부 문서 링크가 그래프의 문서 간 연결로 나타나는 것을 볼 수 있다.
- 관리자는 소주제를 수정·정렬하고, 문서가 연결되지 않은 소주제만 안전하게 삭제할 수 있다.

## 소주제 스키마 전개와 롤백

- 전개는 기존 `pages`를 변경하지 않고 `subtopics`, `page_subtopics`, 조회 인덱스만 추가하는 전진형 변경이다.
- 문서 저장은 대주제–소주제 조합을 검증한 뒤 트랜잭션 안에서 문서와 연결을 함께 반영한다. 잘못된 조합은 전체 롤백한다.
- 기존 스키마에서 두 테이블이 없는 상태를 재현해 초기화한 테스트에서 기존 문서 1개가 그대로 보존됨을 확인했다.
- 애플리케이션 롤백 시 새 테이블은 이전 버전에 영향을 주지 않으므로 그대로 두는 것이 안전하다. 데이터까지 되돌려야 할 때만 백업 후 `page_subtopics`, `subtopics` 순서로 제거한다.

## 문서 링크 스키마 전개와 롤백

- `page_links(source_page_id, target_slug)`는 기존 `pages`를 변경하지 않는 추가형 테이블이며, 원본 문서 삭제 시에만 연결이 cascade 삭제된다.
- 대상은 ID 대신 불변 문서 slug로 보관하므로 아직 생성되지 않은 링크도 저장할 수 있고, 조회 시 공개 대상 문서와 조인한다.
- 테이블이 처음 생성될 때 기존의 검증 가능한 BlockNote 본문을 읽어 내부 링크를 1회 백필하며, 기존 문서와 본문은 수정하지 않는다.
- 애플리케이션 롤백 시 테이블을 남겨도 이전 버전에 영향이 없다. 데이터까지 제거해야 한다면 백업 후 `DROP TABLE page_links`를 수행하는 전진 마이그레이션을 별도로 만든다.

## 알려진 한계

- 계정 설정에서 자율 변경은 가능하지만 최초 로그인 강제 변경과 관리자 재설정은 별도 제품 결정으로 남아 있다.
- Excel multipart 업로드는 선언 크기와 파싱된 `File.size`를 모두 검사하지만, 스트리밍 multipart 파서가 아니므로 배포 프록시의 요청 크기 제한도 유지해야 한다.
- 조회수는 상세 렌더당 증가하며 세션/일 단위 중복 제거와 봇 제외는 하지 않는다.
- 시각 회귀 베이스라인이 없어 픽셀 비교 결과는 산출하지 않았다. 반응형 상호작용, 직접 스크린샷 확인과 axe 검사는 E2E로 검증했다.
- 홈 그래프는 성능을 위해 최근 공개 문서 60개까지만 표시하므로, 문서 간 링크도 양쪽 문서가 이 가시 집합에 포함될 때만 나타난다.
- 문서 간 연결은 검증된 BlockNote 링크 중 같은 서비스의 상대 경로 `/pages/<slug>`만 해석한다. 외부 URL, 다른 경로, 손상 주소는 의도적으로 제외한다.
- 문서가 연결된 소주제는 자동으로 분류를 해제하지 않고 삭제를 막는다. 관리자가 해당 문서를 먼저 옮겨야 한다.
